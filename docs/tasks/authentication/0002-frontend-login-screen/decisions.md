# Decisions

## Scope and Ownership

- Start with login/registration. User-requested follow-ups include DB resets/ingestion, Swagger, testing, and code organization.
- User Service alone accesses User DB. Frontend calls service APIs, never databases. Movie details belong to Movie DB; generated recommendations belong to Recommendation DB.
- Keep public profiles, preferences, watched history, and recommendation features for later tasks.

## Accounts

| Table | Purpose and constraints |
| --- | --- |
| `users` | UUID ID; required email and username, each DB-unique ignoring case; Argon2id password hash; creation/update timestamps. Username is separate from email. |
| `user_profiles` | One per account; display name (can repeat), optional bio, update time. Account deletion cascades. |
| `user_sessions` | Hashed opaque token, account ID, creation/expiry times. Account deletion cascades. |

- `001_accounts.sql` creates the tables; `002_usernames.sql` backfills usernames and enforces required/valid/unique usernames. Email-prefix collisions get numbered suffixes. Startup applies migrations repeatedly under an advisory transaction lock.
- Registration requires username, display name, email, password, and matching confirmation. Username is 1–80 letters/numbers/dots/underscores/hyphens, trimmed/lowercased. Display name is 1–80 characters and can repeat. Email is normalized and limited to 254 characters. Password must be nonempty; no minimum-length policy, per user direction.
- Duplicate username/email return 409 with distinct messages. Missing username has its own required-field error. Login still uses full email and password.
- Registration creates account, profile, and initial session atomically. Sessions expire after seven days, are revalidated on lookup, and rotate on login/registration. Logout removes the session.
- Cookies: HttpOnly, SameSite=Lax, path `/api/user`; Secure by default, false for local HTTP. `AUTH_COOKIE_SECURE` controls HTTPS-only delivery.
- Auth POSTs require JSON and `X-G15-Request: 1`; no CORS grant. Explicit cross-site requests rejected. Errors do not expose DB details; responses disable caching.

## UI

- Palette source: `app/frontend/src/app/assets/palette.json`. Read it before styling; use its colors with accessible foreground/background combinations.
- `g15` is the group number, not the logo. Remove it, brand descriptors, extra story text, posters, and requested introductory copy.
- Desktop split: 40% centered story / 60% form; mobile stacks panels. Keep remaining text readable. Registration heading is “Create your account”, one line with container-scaled font size. Browser title is “Movie Recommendation Hub”.
- `/` redirects to `/login`; `/register` creates an account and signs in; `/account` requires a session; `/health` remains available.
- Use injected BackendService for typed GET/POST, caller headers, and default 8-second timeouts. Auth keeps mutation headers, user/session state, and 15-second login/register timeouts. Health keeps endpoints and readiness validation. Service folders are `shared/services/backend/auth` and `health`.

## DB Tools and Configuration

- One ignored `.env` per backend service configures API and database. Remove root `.env` and its example. Root Compose includes load service env files; standalone DB launchers use the same files and project/volume names.
- Reset is opt-in through `AUTH_RESET_ENABLED` and static private `AUTH_RESET_TOKEN`; not generated by login. Local user env enables it. Defaults/examples remain disabled.
- Reset payload contains only `table`: `all`, `users`, `user_profiles`, or `user_sessions`. Clearing users cascades to profiles/sessions. Reset deletes data transactionally, preserving schema.
- Bruno requests: All, Sessions, Users, Profiles under `DBs/Clear/User`. Use JSON body mode and Auth → Bearer Token with `{{resetToken}}`; remove manual Content-Type/Authorization headers. Bruno token must match the user env value.
- Ingestion lives under `user-service/db/ingestion`, with JSON templates in `assets/`. VS Code task prompts for sample count; default 1,000. Admin is extra and always uses `admin@admin.com` / `admin`; it is a regular account, not an implemented permission role.
- Generate repeatable realistic names, unique usernames/emails, and separate Argon2id hashes. Create profiles but no sessions. Reruns skip generated accounts; lower counts do not delete them. Old sample accounts can be converted without changing IDs.
- Export initial sample/admin login details to ignored `user-service/.run/ingestion-users.csv`. Later password changes are not reflected in that export.

## Swagger, Common Code, and Skills

- Each service owns its OpenAPI JSON and static viewer. Parent viewer in `backend/common/static` has three tabs and fetches those specs; no duplicated API definitions.
- Parent URL: `http://127.0.0.1:4205/api/user/docs/swagger.html`. Service URLs: `/api/<service>/static/swagger.html`. Pinned Swagger UI CDN assets require internet.
- Shared backend layout: `common/db` for SQL loading, `monitoring` for request/DB metrics, `docs` for viewer serving, `static` for viewer HTML. No `src/g15_common` directory; Python import name remains mapped to the root.
- User-directed plugin name/location is `project`, separate from Forge. It packages `swagger`, `run-tests`, and `create-tests` for Codex and Claude Code. Packaging does not imply host installation, activation, or session loading.

## Testing and Script Layout

- Root runner: `scripts/testing/run-tests.sh`; VS Code task: `test: all`. It calls component runners, continues on failures, exits nonzero on failure, and prints per-component and combined totals only.
- Component runners show per-file line/branch tables. Python uses pytest/pytest-cov; frontend uses Angular Vitest/jsdom. Reports and logs are ignored. Combined coverage uses covered/total counts; unavailable coverage is incomplete.
- Python tests mirror source folders. Angular specs sit beside their components/services. Root helper tests mirror `scripts/testing` under `tests/scripts/testing`.
- Script categories: root `development`, `testing`, `validation`; app folders also use `database` and `setup` where needed. Remove `common/scripts`; common tests run from root `scripts/testing/test-common.sh`.
- Test runners do not load app env files or seed/reset running databases. Use mocks/disposable fixtures for external effects.
- `run-tests` runs all suites and replies with totals. `create-tests` starts from measured gaps, respects a narrower user scope, and defaults to 100% per-file executable coverage when scope is absent. Never game coverage by skipping failures or hiding source. Report blockers honestly.
- User authorized repository tests after the initial implementation; the previous no-new-tests record no longer describes final state.

## Model Recommendation Basis

- Reviewed [Codex model guidance](https://learn.chatgpt.com/docs/models) and [Claude model configuration](https://code.claude.com/docs/en/model-config).
- Native Codex availability supports `gpt-6-astra` with medium effort. Reassessed for the expanded frontend, User Service, and database scope; use it as a reliable option for this phase; comparative total-token efficiency is uncertain.
- Claude `sonnet` access is Unverified in this host and its effort is advisory. Reassess both recommendations if the scope changes.
